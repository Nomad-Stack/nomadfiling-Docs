## Nomadfiling-Tools über deinen MCP-Client verwenden

Nomadfiling stellt 14 authentifizierte MCP-Tools bereit, um Einreichungen aufzulisten, zu erstellen, zu aktualisieren und zu löschen, plus Zahlungsverlauf, Faxprotokolle, Formularschemas und PDF-Deep-Links. Nutze diese Seite als Referenz für Tool-Namen, Eingaben, Antwortformen und gängige Anfragemuster.

<Callout kind="info">

Jeder Tool-Aufruf erfordert Authentifizierung über deinen MCP-Client. Richte deine Anmeldedaten ein, bevor du ein Tool aufrufst.

</Callout>

## Tools aus deinem Client aufrufen

Die meisten MCP-Clients verpacken Tool-Aufrufe unterschiedlich, aber die Nutzlastform ist gleich: übergib den Tool-Namen und ein JSON-Objekt mit den Tool-Argumenten.

<CodeGroup tabs="JSON,cURL">

```json
{
  "method": "tools/call",
  "params": {
    "name": "list_filings",
    "arguments": {
      "limit": 10
    }
  }
}
```

```bash
curl -X POST "https://mcp.nomadfiling.com" \
  -H "Authorization: Bearer sk_test_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "method": "tools/call",
    "params": {
      "name": "list_filings",
      "arguments": {
        "limit": 10
      }
    }
  }'
```

</CodeGroup>

Eine erfolgreiche Antwort enthält das in den folgenden Abschnitten definierte Tool-Ergebnis. Tools, die eine bestimmte Einreichung nachschlagen oder ändern, geben einen Fehler zurück, wenn die Einreichung nicht existiert oder nicht dem authentifizierten Nutzer gehört.

## 5472- und 1120-Einreichungstools

Diese Tools arbeiten mit Einreichungsdatensätzen für Einzelmitglieds-Workflows zu Form 5472 und Form 1120.

### list_filings

Listet 5472- und 1120-Einreichungen auf, die dem authentifizierten Nutzer gehören.

<ParamField body="limit" param-type="number" required="false" show-location="false">

Maximale Anzahl zurückzugebender Einreichungen. Standard ist `50`.

</ParamField>

#### Antwort

Das Tool gibt ein Array von Einreichungsübersichtsobjekten zurück.

<ResponseField name="id" field-type="string" required="true">
Eindeutige Einreichungskennung als UUID.
</ResponseField>

<ResponseField name="llc_name" field-type="string" required="true">
Auf dem Einreichungsdatensatz gespeicherter LLC-Name.
</ResponseField>

<ResponseField name="ein" field-type="string" required="true">
Employer Identification Number der Einreichung.
</ResponseField>

<ResponseField name="tax_year_begin" field-type="string" required="true">
Auf der Einreichung gespeichertes Startdatum des Steuerjahres.
</ResponseField>

<ResponseField name="tax_year_end" field-type="string" required="true">
Auf der Einreichung gespeichertes Enddatum des Steuerjahres.
</ResponseField>

<ResponseField name="status" field-type="string" required="true">
Aktueller Einreichungsstatus.
</ResponseField>

<ResponseField name="created_at" field-type="string" required="true">
Zeitstempel, wann die Einreichung erstellt wurde.
</ResponseField>

### create_filing

Erstellt einen neuen 5472- und 1120-Einreichungsdatensatz.

<ParamField body="form_data" param-type="object" required="true" show-location="false">

Vollständige Einreichungsnutzlast. Dieses Objekt enthält die Formularwerte, die von der Nomadfiling-App verwendet werden.

</ParamField>

<ParamField body="llc_name" param-type="string" required="false" show-location="false">

Auf der Einreichungszeile gespeicherter LLC-Name. Wenn weggelassen, fällt das Tool auf `form_data.llcName` zurück.

</ParamField>

<ParamField body="ein" param-type="string" required="false" show-location="false">

Auf der Einreichungszeile gespeicherte Employer Identification Number. Wenn weggelassen, fällt das Tool auf `form_data.ein` zurück.

</ParamField>

<ParamField body="tax_year_begin" param-type="string" required="false" show-location="false">

Auf der Einreichungszeile zu speicherndes Startdatum des Steuerjahres.

</ParamField>

<ParamField body="tax_year_end" param-type="string" required="false" show-location="false">

Auf der Einreichungszeile zu speicherndes Enddatum des Steuerjahres.

</ParamField>

#### Antwort

Das Tool erstellt die Einreichung mit Status `completed` und gibt die neue Einreichungskennung und App-URL zurück.

<ResponseField name="id" field-type="string" required="true">
Neue Einreichungs-UUID.
</ResponseField>

<ResponseField name="view_url" field-type="string" required="true">
App-URL zum Öffnen der Einreichung.
</ResponseField>

<ParamField body="id" param-type="string" required="true" show-location="false">

Einreichungs-UUID.

</ParamField>

<ParamField body="llc_name" param-type="string" required="false" show-location="false">

Aktualisierter LLC-Name.

</ParamField>

<ParamField body="ein" param-type="string" required="false" show-location="false">

Aktualisierte Employer Identification Number.

</ParamField>

<ParamField body="tax_year_begin" param-type="string" required="false" show-location="false">

Aktualisiertes Startdatum des Steuerjahres.

</ParamField>

<ParamField body="tax_year_end" param-type="string" required="false" show-location="false">

Aktualisiertes Enddatum des Steuerjahres.

</ParamField>

<ParamField body="form_data" param-type="object" required="false" show-location="false">

## Gängige Muster

Verwende dieselbe Einreichungs-`id` über die Lookup-, Update-, Delete- und PDF-URL-Tools. Erstellungstools geben die `id` zurück, die du für spätere Operationen benötigst.

<CodeGroup tabs="Erstellen dann abrufen,PDF-URL holen">

```json
{
  "create_filing_result": {
    "id": "a78f82c4-c6af-43ef-bc0a-cbbd7e28db77",
    "view_url": "https://app.nomadfiling.com/filing/a78f82c4-c6af-43ef-bc0a-cbbd7e28db77"
  },
  "next_call": {
    "method": "tools/call",
    "params": {
      "name": "get_filing",
      "arguments": {
        "id": "a78f82c4-c6af-43ef-bc0a-cbbd7e28db77"
      }
    }
  }
}
```

```json
{
  "method": "tools/call",
  "params": {
    "name": "get_pdf_url",
    "arguments": {
      "id": "17a5cb76-e3fe-4a21-b12b-a0a194dfef5a",
      "kind": "partnership"
    }
  }
}
```

</CodeGroup>

<Callout kind="tip">

Wenn du Einreichungsnutzlasten außerhalb der Nomadfiling-App erzeugst, rufe zuerst `get_form_schema` auf, um die erwarteten Feldnamen auf oberster Ebene für den Einreichungstyp zu prüfen, den du erstellen möchtest.

</Callout>

## FAQ

<ExpandableGroup>
<Expandable title="Erfordern alle Tools Authentifizierung?" default-open="true">

Ja. Jedes Nomadfiling-MCP-Tool wird über `tools/call` aufgerufen und erfordert eine authentifizierte MCP-Client-Sitzung.

</Expandable>
<Expandable title="Was passiert, wenn ich optionale Felder beim Erstellen einer Einreichung weglasse?">

Für `create_filing` fällt der Server auf `form_data.llcName` für `llc_name` und `form_data.ein` für `ein` zurück, wenn diese Zeilenfelder weggelassen werden. Für `create_partnership_filing` leitet der Server `llc_name` von `form_data.partnershipName` ab.

</Expandable>
<Expandable title="Was ist der Unterschied zwischen view_url und get_pdf_url?">

`view_url` wird von Create- und Update-Tools als praktischer Link zurückgegeben. `get_pdf_url` löst den Einreichungstyp auf und gibt den Deep-Link zurück, den du später verwenden kannst, wenn du nur eine Einreichungs-`id` hast.

</Expandable>
<Expandable title="Kann ich get_form_schema als vollständige Validierungsspezifikation verwenden?">

Nein. `get_form_schema` gibt Feldbeschreibungen und unterstützte Feldnamen auf oberster Ebene zurück. Nutze es, um Nutzlasten zu formen, aber gehe nicht davon aus, dass es die Validierung auf Anwendungsebene ersetzt.

</Expandable>
<Expandable title="Wie wähle ich zwischen 5472- und Partnerschafts-Tools?">

Verwende das 5472-Toolset für Einzelmitglieds-Einreichungs-Workflows, die in [Form 5472 und 1120](/de/form-5472-1120) dokumentiert sind. Verwende das Partnerschafts-Toolset für Multi-Member-LLC-Partnerschafts-Workflows, die in [Partnerschaftserklärung](/de/partnership-filing) dokumentiert sind.

</Expandable>
</ExpandableGroup>
